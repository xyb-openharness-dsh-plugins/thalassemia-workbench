## 一、问题

重型地贫（TDT）患者从确诊起进入**终身规律输血 + 去铁**的循环。三类长期摩擦：

1. **节律性事实记不住**：每 2–4 周一次输血，输血前 Hb、输注量、有无反应、下次预约日——纸单会丢、相册会乱。
   十年后要回答"一共输过多少次、有没有出现抗体"，没人答得上来。
2. **铁负荷是沉默累积**：铁蛋白每 3 月一次、心肝铁 T2\* 每年一次，家长看不懂这些数字之间的因果关系，
   但**去铁依从与筛查节点一漏，损害已经发生**。工具的价值不是解释因果（那是医生的活），而是让"该做的做了没有"看得见。
3. **决策时刻没有准备**：要不要再生一个（同型配偶风险、产前诊断时点）、要不要考虑移植或基因治疗、
   费用与血源怎么安排——这些都要在门诊里用几分钟谈完，家长手上没有材料。

**本工具不解决**：判读、方案选择、剂量、预后。它只解决"把你看到的事实整理成可以带走的材料"。

## 二、用户与最小闭环

- 主用户：**患儿家长**（记录者），同一账号可切换"本人 / 代记"双视角（R3 形态）。
- 次用户：成年输血依赖型患者本人；家庭成员（只读共享视图）。
- 最小闭环：**记一笔输血 → 回到看板看见下一次该做什么 → 导出一页复诊材料**。

```
选择资料目录
  → 记录一次输血（日期/Hb/量/反应）
  → 看板出现"距下次输血还有 N 天""铁蛋白 3 个月未查"
  → 铁蛋白趋势图上多一个点，事件标记显示当天输过血
  → 就诊准备页汇总"这三个月想问的 5 件事"
  → 导出 Markdown，带去门诊
```

失败恢复：导入失败 → 原文留在资料库、候选可重试；写库失败 → 整体回滚并提示"这次没记上"；
AI 不可用 → 面板降级为"手动整理清单"，核心记录功能不受影响。

## 三、方案与 ADR

| ADR | 决策 | 备选 | 理由 |
| --- | --- | --- | --- |
| ADR-1 | **13 个一级页，含 7 个本品类新增页** | 只做 4 核心模块 | 地贫的信息维度（输血/铁/生长/遗传/费用）在家族里没有承载页；硬塞进"治疗历程"就是换名复用 |
| ADR-2 | **不做任何判读与分级** | 引入铁蛋白/T2\* 阈值分级 | 一条患者视角红线：不做诊断与处置建议。阈值分级会把"参考区间"变成"结论"，且各中心 T2\* 序列不同 |
| ADR-3 | **派生值读取时算**（输血间隔、百分位、逾期天数） | 落库 | 参考标准会升版；落库等于把旧口径写成历史事实 |
| ADR-4 | **原文优先**：报告存原文 + 少量可结构化数值 | 全字段结构化 | T2\* MRI、基因型报告格式极不统一，强行结构化等于假装规范 |
| ADR-5 | 数据全本机 SQLite，无账号 | 云端同步 | 一条红线：患者数据本机优先 |
| ADR-6 | AI 只做"整理与提问"，产出进候选区等核对 | AI 直接写入档案 | 事实四层（文档/候选/记录/指标）不合并 |

## 五、数据与 API

- 表结构见 `docs/SCHEMA.md` 与 `schema/0001_initial.sql`；冻结后只增不改。
- API 前缀 `/api/ferropal-workbench`，页面统一拼 `${API_BASE}/api/xxx`，`API_BASE` 为挂载前缀（独立启动空串，宿主 `/api/ferropal-workbench`）。
- 核心端点：`/health`、`/api/bootstrap`、`/api/transfusions`、`/api/iron`、`/api/growth`、`/api/screening`、`/api/candidates`、`/api/review`。
- 错误语义：4xx 只带 `error` 字段；写操作失败整体回滚；启动校验失败**渲染错误横幅，不裸 throw**。
